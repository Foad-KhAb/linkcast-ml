# LinkCast

An end-to-end ML learning project that predicts how many purchase conversions a
tracking link will bring in the seven days after it is created, using only
information available at creation. Predictions are expected counts (for
example 2.3), so they add up to sensible totals for budgeting.

All data is fictional and generated by the project. Everything runs on a laptop
CPU; no GPU or application database is needed.

## Quick start

Requires Python 3.12 and [uv](https://docs.astral.sh/uv/getting-started/installation/).
From the repository root:

```sh
uv sync --locked
./scripts/run_pipeline.sh
```

The script runs every step below in order and takes about three to four minutes. It
writes fictional data to `data/synthetic/`, the saved model to
`artifacts/linkcast-model/`, and JSON reports and example predictions to
`runs/latest/`. All three directories are ignored by Git and can be recreated
at any time; the same seed always produces the same results. Override the
defaults with environment variables, for example `SEED=11 ./scripts/run_pipeline.sh`.

## Pipeline

| Step | Command | What it does |
| --- | --- | --- |
| Generate | `linkcast generate` | Fictional source tables and one schema-1.0 row per link |
| Validate | `linkcast validate FILE` | Checks rows against the dataset contract |
| Inspect | `linkcast inspect FILE` | Label maturity, target shape, missingness, new entities, checks |
| Split | `linkcast split FILE` | Chronological train/validation/test respecting label availability |
| Baseline | `linkcast baseline FILE` | Smoothed historical means, tuned on validation |
| Train | `linkcast train FILE` | CatBoost Poisson models tuned and compared on validation |
| Evaluate | `linkcast evaluate FILE` | Refit chosen models and score the test split once |
| Save | `linkcast save FILE` | Train the chosen model on all available labels and save it |
| Predict | `linkcast predict MODEL FILE` | Expected conversions for new links |

Prefix each command with `uv run --locked`. `FILE` is a schema-1.0 JSONL file,
such as `data/synthetic/link_rows.jsonl`. `linkcast COMMAND --help` lists each
command's options.

## Dataset contract

Dataset schema 1.0 is defined and validated in `src/linkcast/schema.py`. Data is
stored as UTF-8 JSON Lines, one flat object per link. The main rules:

- One row per link, predicted at `created_at` using only information available
  by then (`features_available_at <= created_at`).
- The target `purchase_conversions_7d` counts approved purchase conversions in
  `[created_at, created_at + 168 hours)`.
- `label_status` is `ready` (complete tracking, label available after the window
  and reporting delay), `pending`, or `unknown`. Pending and unknown rows keep a
  null target. A 24-hour-old link stays in the dataset with partial observations,
  not a completed label.
- Unknown values are `null` and are never treated as zero. Unmeasured post views
  and unknown tracking coverage are not zero views or zero conversions.
- Model inputs come from an explicit allowlist; labels and audit fields are never
  inputs. Unknown columns are rejected.

`examples/link_rows_v1.jsonl` holds three hand-written rows (a completed zero, a
pending label, and an unknown label). `examples/new_links_v1.jsonl` holds two
new links at creation, used to demonstrate prediction.

## Synthetic data

`linkcast generate` (default seed 7) simulates 20 stores, 80 publishers, 150
media, and about 20,000 links over 182 days starting 2026-01-01. Some stores and
media first appear late so evaluation can test unseen entities. `--seed`,
`--days`, and `--media` change the run. The output directory contains:

- `sources/`: fictional source tables (stores, media, campaigns, creatives,
  landings, links, posts, post-link associations, view and audience
  observations, conversions, tracking reviews), each with occurrence,
  measurement, or receipt timestamps.
- `link_rows.jsonl`: one row per link. Features use only source records
  available at link creation; labels use only matured, reviewed windows with
  complete tracking.
- `truth/`: hidden simulator variables, such as media quality and each link's
  expected seven-day count. They drive the simulation but never appear in
  sources or link rows; they are for checking the pipeline, not for training.
- `manifest.json`: configuration, generator version, and row counts.

Conversions follow a negative binomial (gamma-Poisson) process: most links get
zero or a few conversions and a few get many. Some post views are unmeasured,
some links have tracking outages or unverified coverage (label `unknown`), and
recent links remain `pending` with partial counts.

## Inspection

`linkcast inspect` should run before splitting or training. It reports label
status per creation month and the first day whose labels are mostly still
pending; the ready target's mean, variance, zero share, and upper quantiles;
missing-value shares per feature and month; stores, media, campaigns, and
creatives first seen each month; and checks (model inputs exclude labels and
audit fields, feature timestamps precede creation, one snapshot time, no stale
pending labels, unknown-label share, constant features, month-to-month
missingness shifts). Failing checks exit with status 1; warnings are for review.

## Chronological splits

Defaults match the default synthetic data and can be changed with
`--train-cutoff`, `--validation-end`, and `--test-end` (UTC dates) on `split`,
`baseline`, `train`, `evaluate`, and `save`:

| Set | Rule (defaults) | Use |
| --- | --- | --- |
| `train` | label available by 2026-05-01 | Fit models compared on validation |
| `validation` | ready label, created 2026-05-01 to 2026-05-31 | Compare and tune models |
| `in_final_train` | label available by 2026-06-01 | Refit once before testing |
| `test` | ready label, created 2026-06-01 to 2026-06-22 | Final score, used once |
| `excluded` | everything else, with a reason | Never fitted or scored |

Training eligibility depends on when the label became **available**, not on
when the link was created. Links created in the roughly ten days before a
cutoff are excluded (`label_after_cutoff`) because their seven-day outcomes were
not known yet. Pending and unknown labels are never trained on or scored.
Evaluation rows are flagged when their store, media, campaign, or creative never
appears in their training set. `split` writes `splits.csv` next to the dataset.

## Scores

| Score | Meaning |
| --- | --- |
| MAE | Mean absolute error in conversions per link |
| Poisson deviance | Quality of predicted averages for counts; lower is better; used to choose settings |
| Bias | Mean prediction minus mean actual; near zero means totals are not systematically off |
| Total error | \|predicted total - actual total\| / actual total, overall and summed per store and per campaign |

MAE is minimized by a median, whereas these models predict means for budgeting.
On skewed counts, a constant median can beat an informative mean-based model on
MAE alone, so settings are chosen by Poisson deviance.

## Models

**Baseline.** Predicts training-set averages, falling back from media to store
to platform to the global mean, with each level smoothed toward the level above:

```text
estimate = (group conversions + k * parent estimate) / (group links + k)
```

`k` is chosen from `--grid` by validation Poisson deviance. The report also
shows constant mean and median predictions and scores by fallback level.

**CatBoost.** Poisson loss on two feature sets: the default 10 creation-time
inputs and all 29 allowed candidates. For each set, tree depths 4, 6, and 8 and
learning rates 0.03 and 0.1 are tried, early stopping on validation picks the
number of trees, and the lowest validation Poisson deviance wins. Identity
fields are categorical; unknown categories become an explicit missing category
and unknown numbers stay missing. `train` reports both models against the
baseline with feature importances.

## Evaluation

`linkcast evaluate` makes every choice on validation (baseline `k`, CatBoost
settings, and the chosen feature set), refits the models on `in_final_train`,
and scores the test split once. Test labels are used only for scoring. The
report shows overall scores, scores for links on new vs known stores, media,
campaigns, and creatives, and mean predicted vs mean actual conversions in five
bands of the chosen model's predictions. No calibration correction is applied;
bias is reported as observed.

Results with the default seed (test split, 2,602 links):

| Model | MAE | Poisson deviance | Bias | Total error by store |
| --- | --- | --- | --- | --- |
| Baseline | 1.493 | 2.496 | -0.07 | 29.5% |
| CatBoost, 10 features | 1.418 | 2.335 | -0.12 | 19.7% |
| CatBoost, 29 features (chosen) | 1.425 | 2.299 | -0.08 | 19.3% |

CatBoost under-predicts links on new campaigns and creatives and is close to
unbiased on known ones. These numbers show that the pipeline behaves correctly
on synthetic data; they say nothing about real business value.

## Saved model and prediction

```sh
uv run --locked linkcast save data/synthetic/link_rows.jsonl
uv run --locked linkcast predict artifacts/linkcast-model examples/new_links_v1.jsonl
```

`save` makes the same validation choices, then trains the chosen model on every
label available at the dataset's snapshot time, because a deployed model should
learn from everything known. Its expected quality is the test score from
`evaluate`. The artifact directory contains `model.cbm` (CatBoost's native
format) and `metadata.json`: schema and package versions, the exact feature
list, settings, training cutoff and size, validation scores behind the choice,
entities seen in training, and the data manifest.

`predict` reads schema-1.0 rows at link creation (labels, if present, are
ignored) and outputs `expected_conversions_7d` per link, with `new_store`,
`new_media`, `new_campaign`, and `new_creative` flags for entities absent from
training. Treat predictions for new campaigns and creatives with care, since
evaluation shows they tend to be too low. `--out` writes a CSV instead of
printing.

## Development

```sh
uv run --locked pytest
uv run --locked ruff check .
uv run --locked ruff format --check .
```

`uv sync` creates `.venv/` and installs the package in editable mode from
`pyproject.toml`; `uv.lock` pins exact dependency versions and is version
controlled. Dependencies: CatBoost for tabular modeling, pandas and NumPy for
data handling, scikit-learn; pytest and Ruff for development.

```text
src/linkcast/       schema, generate, inspection, splits, metrics, baseline,
                    model, evaluate, artifact, cli
scripts/            run_pipeline.sh: the full pipeline in one command
examples/           Hand-written fictional rows
tests/              Tests for each module and the CLI
```
